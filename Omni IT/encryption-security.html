مقدمة عن التشفير

التشفير هو عملية تحويل البيانات إلى صيغة غير مفهومة بدون المفتاح. يستخدم للحفاظ على سرية البيانات والتحقق من سلامتها وضمان عدم إنكار الرسالة.

أنواع التشفير مع أمثلة عملية

1. التشفير المتماثل (Symmetric Encryption)
   ├─ التعريف: نفس المفتاح للتشفير وفك التشفير
   ├─ الخصائص:
   │  ├─ سريع جداً
   │  ├─ كفء للبيانات الكبيرة
   │  └─ التحدي: مشاركة المفتاح بأمان
   │
   └─ أمثلة واقعية:
      • AES (Advanced Encryption Standard)
        - تموضع: حماية ملفات Windows
        - مثال: تشفير ملف Word بكلمة مرور
        - الخطوات:
          1. أكتب الملف في Word
          2. حفظ مع كلمة مرور
          3. الملف الآن مشفر بـ AES-256
          4. لا أحد يستطيع فتحه بدون الكلمة
      
      • DES (Data Encryption Standard) - قديم
        - لا يستخدم الآن لأنه ضعيف
        - تم اختراقه في الماضي
      
      • 3DES (Triple DES)
        - تطبيق DES ثلاث مرات
        - أقوى من DES لكن أبطأ

2. التشفير غير المتماثل (Asymmetric Encryption)
   ├─ التعريف: مفتاح عام (Public) ومفتاح خاص (Private)
   ├─ الخصائص:
   │  ├─ آمن جداً
   │  ├─ بطيء للبيانات الكبيرة
   │  └─ حل مشكلة مشاركة المفتاح
   │
   └─ أمثلة واقعية:
      • RSA (Rivest-Shamir-Adleman)
        - الأكثر شيوعاً
        - تطبيق: HTTPS (المواقع الآمنة)
        
        مثال عملي:
        Alice تريد إرسال رسالة لـ Bob بأمان
        ├─ Bob يرسل مفتاحه العام لـ Alice
        ├─ Alice تشفر الرسالة بالمفتاح العام
        ├─ ترسل الرسالة المشفرة (أي أحد يستطيع فكها؟ خطأ!)
        ├─ Bob يستقبل الرسالة
        ├─ Bob يفك التشفير بمفتاحه الخاص
        └─ Alice: "مرحباً Bob"
           Bob يعرفها من توقيعها
      
      • ECC (Elliptic Curve Cryptography)
        - أقوى من RSA بمفتاح أقصر
        - الاستخدام: iOS و Android
        - مثال: WhatsApp يستخدم ECC

3. دوال التجزئة (Hashing)
   ├─ التعريف: تحويل البيانات لرمز ثابت الطول
   ├─ الخصائص:
   │  ├─ لا يمكن فك التشفير (one-way)
   │  ├─ أي تغيير يغير الناتج كلياً
   │  └─ سرعة جداً
   │
   └─ أمثلة واقعية:
      • MD5 (قديم - لا تستخدمه)
        - مثال: hash("password") = 5f4dcc3b5aa765d61d8327deb882cf99
        - تم اختراقه
      
      • SHA-256 (الآن الشائع)
        - مثال: 
          hash("password") = 
          5e884898da28047151d0e56f8dc62927
          75c9b86ecb6670d45397e29e5b9b8baf
        
        الاستخدامات:
        ├─ تخزين كلمات المرور
        │  المثال: في الفيسبوك
        │  لا يحفظ كلمة المرور مباشرة
        │  يحفظ: hash_of_password
        │
        ├─ فحص سلامة الملفات
        │  تحميل برنامج من الإنترنت
        │  يحسب hash الملف
        │  يقارنه بـ hash الرسمي
        │  إذا تطابقا: الملف آمن
        │
        └─ البلوكتشين (Bitcoin)
           كل كتلة تحتوي على hash الكتلة السابقة
           إذا غيرت كتلة واحدة تنقطع السلسلة كلها

HTTPS و SSL/TLS - المواقع الآمنة

الفرق بين HTTP و HTTPS:

HTTP (غير آمن)
├─ مثال: http://website.com
├─ البيانات مُرسلة بدون تشفير
├─ أي أحد يستطيع اعتراضها
└─ تحذير: لا تستخدمه لتحويل أموال

HTTPS (آمن جداً)
├─ مثال: https://bank.com (لاحظ الأقفال الأخضر)
├─ البيانات مُشفرة بـ TLS
├─ SSL Certificate يثبت هوية الموقع
└─ آمن جداً للتحويلات المالية

مثال عملي:
1. تسجيل الدخول للبنك
   ├─ المتصفح يطلب HTTPS connection
   ├─ البنك يرسل SSL Certificate
   ├─ المتصفح يتحقق من الشهادة
   ├─ يتم إنشاء فتحة آمنة
   └─ كلمة المرور مشفرة كلياً

2. التسوق على أمازون
   ├─ أنت تدخل بيانات بطاقتك الائتمانية
   ├─ يتم تشفيرها بـ RSA + AES
   ├─ السيرفر يحصل على البيانات
   ├─ يتم فك التشفير
   └─ البيانات محفوظة آمنة

الشهادات الرقمية (Digital Certificates)

ما هي شهادة SSL/TLS؟
├─ وثيقة تثبت هوية الموقع
├─ توقيعة من جهة موثوقة (CA)
└─ تحتوي على المفتاح العام

مثال عملي:
عندما تذهب لموقع البنك:
├─ المتصفح يطلب الشهادة
├─ البنك يرسل شهادته
├─ المتصفح يتحقق:
│  ├─ هل الشهادة صالحة؟
│  ├─ هل صادرة من جهة موثوقة؟
│  ├─ هل اسم الموقع متطابق؟
│  └─ هل انتهت صلاحيتها؟
└─ إذا كل شيء تمام: يظهر الأقفل الأخضر

معلومات الشهادة:
├─ اسم الموقع: bankofamerica.com
├─ المفتاح العام: (رقم كبير)
├─ تاريخ الانتهاء: 2025-06-15
├─ جهة الإصدار: VeriSign
└─ رقم تسلسلي: 12345...

التوقيع الرقمي (Digital Signature)

ما هو التوقيع الرقمي؟
├─ إثبات هوية المرسل
├─ ضمان عدم التعديل على البيانات
└─ حل قانوني لسند المستندات

كيفية العمل:
Alice تريد توقيع وثيقة رقمياً
├─ تحسب hash الوثيقة
├─ تشفر ال hash بـ private key
├─ ترسل الوثيقة + التوقيع
├─ Bob يستقبل الوثيقة
├─ فك التشفير بـ public key من Alice
├─ يحسب hash الوثيقة نفسه
├─ يقارن الهاش:
│  ├─ متطابق = الوثيقة أصلية + من Alice
│  └─ مختلف = تم التعديل عليها
└─ ✅ البيانات موثوقة وآمنة

الفرق بين التوقيع والتشفير:
├─ التشفير: حماية السرية (يقرأها من يملك المفتاح)
├─ التوقيع: إثبات الهوية (من أرسلها؟)
└─ معاً: أمان كامل

إدارة المفاتيح (Key Management)

أحد أهم جوانب الأمان السيبراني - كيفية حفظ ومشاركة المفاتيح بأمان:

مشاكل إدارة المفاتيح

  • التوليد: كيفية إنشاء مفاتيح قوية حقاً؟
  • التخزين: أين نحفظها بدون اختراق؟
  • المشاركة: كيف نرسل المفتاح بأمان؟
  • التناوب: متى نغيرها؟
  • الإلغاء: كيف نلغي مفتاح تعرض للخطر؟

حلول عملية

1. استخدام HSM (Hardware Security Module)
   ├─ جهاز فيزيائي يخزن المفاتيح
   ├─ لا يمكن استخراج المفاتيح من الجهاز
   ├─ العمليات تحدث داخل الجهاز
   └─ البنوك والحكومات تستخدمه

2. Key Derivation Functions
   ├─ اشتقاق مفاتيح من كلمة مرور
   ├─ مثال: في الـ Backup الآمن للهاتف
   └─ بطيء ومقصود (لمنع الهجمات القاسية)

3. Secrets Management Tools
   ├─ Vault: تخزين آمن للكلمات السرية
   ├─ AWS Secrets Manager
   └─ كلود يحرس المفاتيح

أنواع الهجمات على التشفير

Brute Force Attack

محاولة كل الاحتمالات الممكنة:

  • المثال: كلمة مرور 4 أرقام - 10,000 احتمال فقط
  • الحل: كلمات قوية + timing delays
  • السرعة: بطيء جداً مع التشفير القوي

Dictionary Attack

استخدام قائمة بكلمات شائعة:

  • المثال: "password123" في قاموس معروف
  • الحل: Salting - إضافة عشوائيات
  • الفائدة: أسرع من Brute Force

Man-in-the-Middle (MITM)

اعتراض البيانات بين طرفين:

بدون حماية:
Alice → [Data] → Bob
       ↳ Eve تعترض البيانات

مع SSL/TLS:
Alice → [Encrypted Data] → Bob
       ↳ Eve ترى فقط أرقام غير مفهومة

Rainbow Table Attack

استخدام جداول معدة مسبقاً بـ hashes:

  • الفكرة: hash("pass123") = xyz123 (محفوظ مسبقاً)
  • الحل: bcrypt, argon2 - hashing آمن مع salt
  • الفائدة: تحويل الـ hash السريع إلى عملية بطيئة

Side-Channel Attacks

الهجوم على تفاصيل التنفيذ وليس الخوارزمية:

  • Timing Attack: قياس وقت المقارنة
  • Power Analysis: قياس استهلاك الكهرباء
  • Electromagnetic: التقاط الإشارات المغناطيسية

Perfect Forward Secrecy (PFS)

ميزة لتجنب كارثة كبرى - حتى لو تعرض المفتاح الطويل الأمد للخطر:

سيناريو بدون PFS:
1. تشفير جميع الاتصالات بـ master key
2. تعرض master key للاختراق بعد سنة
3. هاكر فك تشفير جميع الاتصالات القديمة
4. كارثة! جميع الرسائل السابقة مفضوحة

مع PFS:
1. كل جلسة تستخدم مفتاح مؤقت (Session Key)
2. المفتاح ينتهي مع نهاية الجلسة
3. تعرض master key بعد سنة
4. لا يؤثر على الجلسات القديمة
5. آمان! الرسائل القديمة آمنة

كيف يعمل:
├─ ECDHE (Elliptic Curve Diffie-Hellman)
├─ كل طلب يولد مفتاح جديد مؤقت
└─ HTTPS الحديث يستخدمه افتراضياً

Quantum Computing والتشفير

التطور المستقبلي الذي قد يغير كل شيء:

المشكلة

  • الكمبيوتر العادي: 1 غيغاهرتز = مليار عملية/ثانية
  • كمبيوتر كمي: يعالج احتمالات متعددة معاً (superposition)
  • النتيجة: RSA ستنكسر في ساعات بدل ملايين السنين

الحل: Post-Quantum Cryptography

  • Lattice-based: CRYSTALS-Kyber (NIST approved)
  • Hash-based: XMSS, LMS
  • Multivariate: Rainbow

الخط الزمني: كمبيوترات كمية عملاقة متوقعة بعد 10-20 سنة. البنوك والحكومات تستعد الآن.

نصائح أمنية مهمة

1. استخدام كلمات مرور قوية
   ❌ ضعيفة: password, 123456, facebook
   ✅ قوية: Tr0pic@lSunset!2024
   
   معايير:
   ├─ طول أكثر من 12 حرف
   ├─ أحرف كبيرة وصغيرة
   ├─ أرقام وعلامات خاصة
   └─ لا تحتوي على معلومات شخصية

2. مدير كلمات المرور (Password Manager)
   ├─ 1Password, LastPass, Bitwarden
   ├─ يحفظ جميع الكلمات بتشفير قوي
   ├─ أنت تتذكر كلمة واحدة فقط
   └─ يملأ الحقول تلقائياً بأمان

3. تفعيل المصادقة الثنائية (2FA)
   ├─ Gmail: البريد + رمز من الهاتف
   ├─ البنك: البطاقة + رمز SMS
   ├─ Authenticator App (أفضل من SMS)
   └─ حماية قصوى ضد الاختراق

4. تحديث البرامج دوري
   ├─ Windows Update: نطبق الرقع
   ├─ تطبيقات الهاتف: حدث دائماً
   ├─ المتصفح: تحديثات أمان مستمرة
   └─ منع الثغرات الأمنية

5. حذر من التصيد (Phishing)
   ├─ البريد يبدو من البنك
   ├─ الفحص: ضع الفأرة على الرابط
   ├─ التحقق من عنوان الموقع (URL)
   └─ لا تدخل بيانات على روابط غريبة

6. استخدام VPN في الأماكن العامة
   ├─ WiFi المقهى: غير آمنة جداً
   ├─ VPN: تشفر جميع البيانات
   ├─ يخفي عنوان IP الحقيقي
   └─ تصفح آمن = نعم

7. الاطلاع على سياسات الخصوصية
   ├─ متى تتشفر البيانات؟
   ├─ كم شركة ترى البيانات؟
   ├─ هل تستخدم E2E Encryption؟
   └─ مثال: WhatsApp يستخدمها، Facebook لا
